## 1. Проблема (AS IS)

### 1.1 Симптомы

На PR #19 релизный гейт упёрся в отсутствие вердикта ревью:

1. **Мерж закрыт навсегда** — не из-за проблем с кодом, а потому что вердикт выносить некому
2. **Замечания заказчика не доезжают до разработчика** — шесть замечаний висят в PR, но круг правок их не берёт в работу
3. **Гейт делает 4 попытки запросить `/review`** и упирается в потолок ожидания

### 1.2 Наблюдения

**Факты с код-доказательствами:**

1. В `.github/workflows/` есть только `tests.yml` — workflow для ревью отсутствует
   - `.github/workflows/tests.yml:1-17`

2. Релизный гейт ожидает вердикт ревью через модуль `review.py`:
   - `poh_delivery/review.py:1537-1642` — реализация логики вердикта
   - `poh_delivery/review.py:1585-1595` — функция `review_head()` ищет коммит в комментариях PR-Agent
   - `poh_delivery/review.py:1609-1642` — функция `verdict()` возвращает `NONE` если ревью не проводилось

3. Правила классификации превращают `NONE` в `REVIEW_PENDING`:
   - `poh_delivery/rules.py:1734-1736`
   - `poh_delivery/rules.py:1659` — константа `REVIEW_PENDING = "review-pending"`

4. Круг правок читает ревью через комментарии PR (тело ревью или построчные замечания):
   - Контекст из задачи: «Круг правок читает ревью — тело ревью и построчные замечания»

### 1.3 Корневая причина

**В репозитории отсутствует workflow для запуска PR-Agent.**

Отсутствие workflow означает:
- Нет автоматического запуска ревью при открытии PR
- Команда `/review` ни к чему не привязана
- PR-Agent не оставляет комментарий с коммитом («review updated until commit ...»)
- Функция `review_head()` возвращает пустую строку
- Вердинкт становится `NONE` → `REVIEW_PENDING` → релиз блокируется навсегда

## 2. Требования (TO BE)

### 2.1 Функциональные требования

| ID | Требование | Признак выполнения |
|----|------------|---------------------|
| ТР-1 | Ревью запускается автоматически при открытии PR | В Actions появляется запуск workflow `pr-review.yml` на событие `pull_request:opened` |
| ТР-2 | Ревью перезапускается по команде `/review` | Комментарий `/review` в PR запускает workflow заново |
| ТР-3 | PR-Agent оставляет комментарий с коммитом | В PR появляется комментарий с текстом «review updated until commit <sha>» |
| ТР-4 | Релизный гейт получает вердикт | Статус PR меняется с `REVIEW_PENDING` на другой (`CLEAN`, `CHANGES`, `BLOCKED`) |
| ТР-5 | Круг правок видит замечания | Замечания формального ревью (review comments) появляются в работе круга правок |
| ТР-6 | Вердинкт привязан к коммиту | При новом коммите вердикт устаревает (`STALE`) до следующего ревью |

### 2.2 Нефункциональные требования

| ID | Требование | Значение / Порог |
|----|------------|-------------------|
| НТР-1 | Время ответа ревью | ≤ 20 минут (timeout в демо-воркфлоу) |
| НТР-2 | Совместимость с существующими workflow | Не затрагивает `tests.yml` и правила слияния |
| НТР-3 | Повтор при rate-limit | Одна попытка с паузой 90 секунд (как в демо) |

### 2.3 Ограничения

| ID | Ограничение | Следствие |
|-----|-------------|-----------|
| ОГР-1 | Не трогать код Delivery-Agent | Изменения только в `.github/workflows/` |
| ОГР-2 | Использовать тот же механизм, что в демо | Копировать подход из `poh-demo-checkout` с адаптацией под Python |
| ОГР-3 | Права токена GitHub App | Пуш в `.github/workflows/` требует права `workflows`; при отсутствии — пуш упадёт |

## 3. Решение

### 3.1 Компоненты для добавления

#### 3.1.1 `.github/workflows/pr-review.yml`

**Назначение:** Workflow для запуска PR-Agent на ревью PR.

**Источник:** Адаптация `po-helper-org/poh-demo-checkout/.github/workflows/pr-review.yml`

**Ключевые особенности:**
- Триггеры: `workflow_call`, `issue_comment` (команда `/review`), `pull_request:opened`
- Использует CLI-образ pr-agent через Docker (одинаково работает с обоих входов)
- Оставляет комментарий с коммитом (pr-agent делает это автоматически)
- Отправляет событие в Issue Agent (опционально, если секреты настроены)

**Адаптация под Python:**
- Изменений в конфигурации pr-agent не требуется
- pr-agent анализирует код независимо от языка (Python/Node)
- Единственное отличие — паттерны кода в анализе, но это работает из коробки

### 3.2 Изменения в существующих компонентах

**Отсутствуют.** Согласно ограничению ОГР-1, код Delivery-Agent не меняется:
- `tests.yml` — не трогаем
- `poh_delivery/review.py` — уже готов работать с вердиктом
- `poh_delivery/rules.py` — уже классифицирует по вердикту
- Правила слияния — не трогаем

### 3.3 Интеграция с существующей системой

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         Поток данных                                     │
└─────────────────────────────────────────────────────────────────────────┘

PR открыт → pr-review.yml → PR-Agent → комментарий с коммитом
                                          ↓
                              формальное ревью (замечания)
                                          ↓
                                    Круг правок читает ревью
                                          ↓
                                    Развитие агента правит код
                                          ↓
                                    Комментарий "/review"
                                          ↓
                                    pr-review.yml перезапускается
                                          ↓
                                    PR-Agent ревьюит новый коммит
                                          ↓
                                    Вердинкт CLEAN → релиз берёт PR
```

## 4. Риски и митигации

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| У GitHub App нет права на workflows | Высокая | Критическое | Проверить права до задачи; при отсутствии — файл добавит человек |
| Rate-limit LLM API | Средняя | Высокое | Одна попытка с паузой 90 сек (уже в демо) |
| pr-agent не запускается в контуре | Низкая | Среднее | Проверить секреты `LLM_API_KEY`, `LLM_MODEL`, `LLM_BASE_URL` |
| Комментарий PR-Agent не парсится | Низкая | Критическое | Паттерн уже проверен в `review.py:1581-1582` |

## 5. Определение готовности

Задача считается выполненной, когда:

1. ✅ В репозитории появился файл `.github/workflows/pr-review.yml`
2. ✅ На PR #19 (или новом тестовом PR) ревью запустилось автоматически
3. ✅ Команда `/review` перезапускает ревью по текущему коммиту
4. ✅ В PR появился комментарий PR-Agent с текстом «review updated until commit ...»
5. ✅ Формальное замечание (review comment) видимо кругу правок
6. ✅ Круг правок берёт замечание в работу
7. ✅ После устранения замечаний появляется вердикт «замечаний нет»
8. ✅ Релиз перестаёт упираться в «verdiktа нет»
