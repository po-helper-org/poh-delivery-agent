# Delivery-Agent: состояние на 26 августа 2026

Документ для передачи работы. Что сделано и проверено, что заблокировано, где
лежат заплатки и с чего продолжать. Ведётся как рабочая записка, а не как
маркетинг: если что-то держится на скотче, здесь про скотч написано.

## Готово и проверено живыми прогонами

| Возможность | Чем доказано |
|---|---|
| Отбор PR: одобрение человека **и** вердикт ревью по текущему коммиту | `poh-demo-checkout#113` — метка `needs-human:pr` закрыла мерж, релиз не заводился |
| Свежесть вердикта по коммиту, а не по PR | правка после вердикта аннулирует его; источники — формальное ревью, построчные замечания, комментарий ревьюера-бота |
| Круг «ревью → правки» силами агента разработки | `poh-issue-agents#262` — четыре круга по замечаниям заказчика |
| Конфликты отдаются агенту разработки | `poh-demo-checkout` #6, #35, #38 — по одноразовому контейнеру на PR |
| Учёт потерянных строк при разрешении конфликта | #35 — «исчезло строк: 9», написано в PR |
| Очередь по риску и зависимостям файлов | таблица очереди в теле каждого релиза |
| Черновик релиза до мержа, ссылка во всех входящих PR | релизы `release-2026-08-24.*` |
| Контракт проверок перечитывается из влитого состояния | `poh-delivery-agent#7` — иначе релиз откатывал сам себя |
| Окно наблюдения после выкатки | `release-2026-08-26.1` — убил контейнер на 10-й секунде окна, релиз поймал и откатил; `release-2026-08-26.2` — здоровый прогон, окно 121 с, публикация |
| Откат: `git revert` + возврат прежней сборки + остановка очереди | сработал дважды: на красной проверке (#35) и на смерти в окне (#156) |

Порядок шага сейчас: пересъём фактов → мерж → перечитывание контракта проверок →
выкатка → проверки → окно наблюдения → повторные проверки → вердикт.

## Не сделано

### Предпосылки для настоящего прода

1. **Адаптер деплоя.** Прод — контейнер на хосте воркера из клона репозитория.
   Ни Dokploy, ни k8s, ни systemd не поддержаны. Для реального сервиса выкатки нет.
2. **Данные и миграции.** `git revert` возвращает код, но не схему БД. PR с
   миграцией откатывается вслепую. Пока правило не описано — на сервисе с базой
   применять нельзя.

### Очередь доработок

3. **Автостарт релиза по одобрению PR.** Триггер только ручной `/release`;
   вебхук не подписан на `pull_request` и `pull_request_review`.
4. **Блокировка потери работы при разрешении конфликта.** Исчезнувшие строки
   считаются, но мерж не останавливается.
5. **Ревью по требованию.** У GitHub App один адрес вебхука, он занят
   Issue-Agent; ревьюер контура узнаёт о PR обходом раз в 5 минут, `/review` до
   него не доходит. Нужен второй App либо маршрутизация событий.
6. **Постепенная выкатка.** Один инстанс, замена целиком: ни канареек, ни доли
   трафика.
7. **Сигналы наблюдения.** Только состояние контейнера и HTTP-проверки.
   Деградация, при которой сервис жив и отвечает 200, окном не ловится.
8. **Репозиторий без сервиса.** Нет `checks.json` — шаг падает на выкатке и PR
   откатывается, хотя документация обещает «релиз пойдёт, проверять нечем».
9. **Кроссрепозиторные релизы** не поддержаны.

## Заплатки на стенде (не в репозиториях!)

`/etc/dokploy/compose/compose-connect-redundant-system-mzso3q/code/harness/`

- `docker-compose.override.yml` — лимиты памяти нашим контейнерам и **сужённый
  список репозиториев ревьюера**: в общем `WATCHED_REPOS` лежит цель GitLab-демо,
  на которой PR-Agent получает 404 и падает целиком, не обойдя остальные.
- `.env`: `COMPOSE_PROFILES=pr` (ревьюер контура на стенде), `PR_APP_*`
  заполнены значениями `ISSUE_APP_*` — второго GitHub App нет, оба агента ходят
  одним, ключ и модель берутся из этого же `.env`.
- `DEVELOP_TEST_COMMAND` сделан репозиторно-зависимым: pytest для репозиториев с
  `pyproject.toml`, иначе прежняя команда Node.

Всё это переживёт перезапуск, но не переезд на другой хост и не факт, что
переживёт панельный деплой Dokploy. Правильное место для этого — `poh-infra`.

## Что выключено на стенде

Чтобы освободить память под прогоны, остановлены Repowise (6 контейнеров) и
`harness-memory-memory-api`. Аналитика при этом работает без индекса кода
(`repowise-dialog` пустой), а в тело релиза не подмешивается блок накопленного
опыта организации. Вернуть:

```bash
docker start poh-repowise-proxy-1 poh-repowise-repowise-contour-mcp-1 \
  poh-repowise-repowise-product-mcp-1 poh-repowise-caddy-1 \
  poh-repowise-indexer-1 poh-repowise-repowise-web-1 harness-memory-memory-api-1
```

**Важно:** индексатор Repowise течёт зомби-процессами — за сутки набрал 1846
штук и загнал хост в load average 128. После включения за ним стоит следить.

## Дефекты контура, найденные по дороге

- **Реплика заказчика в Issue роняет цикл**: `interpret_user_comment` падает с
  `'dict' object has no attribute 'repo'`, воркфлоу задачи уходит в FAILED.
  Обход: вести задачи метками и формальными ревью в PR, не комментариями в Issue.
- **Круг уточнений публикует дамп артефакта** (`repowise-dialog.md` с сырым
  JSON) вместо вопроса — дважды подряд на одной задаче.
- **Ревьюер подтягивает тикет из чужого репозитория**: к PR в
  `poh-delivery-agent` пришли замечания про `POST /stats` из `poh-demo-checkout`.
- **Аналитика выдумывает якоря**: `workflow.py:2054-2077` при 490 строках в
  файле, и так все пять ссылок в документе.
- **Декомпозиция плодит шум**: подзадачи «Сомнения», «Допущения», «Намерение».

## Как продолжать

Роли: заказчик открывает задачу, читает артефакты, ревьюит PR формальным ревью
(только его читает круг правок), ставит `ready-to-ship` и принимает в проде.
Код пишет контур.

Запуск круга правок вручную, когда цикл задачи умер:

```bash
docker exec -i <issue-worker> python - <<'PY'
import asyncio
from shared.temporal_client import connect_temporal
async def main():
    c = await connect_temporal()
    h = await c.start_workflow("IssuePrFix", args=["owner/repo", PR, ROUND],
                               id=f"prfix-owner/repo-PR-manual-ROUND",
                               task_queue="issue-lifecycle")
    print(h.id)
asyncio.run(main())
PY
```

Приёмка окна наблюдения — `docker kill poh-delivery-prod` в середине окна.
Ни строчки кода для этого не нужно, и подыграть себе нечем.
