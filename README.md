# poh-delivery-agent

**Delivery-Agent — релиз-менеджер контура производства.**

Миссия и зона ответственности: доставить одобренные PR до прода и проконтролировать,
что система работает ровно так, как описано в БФТ.

Статус: **исследование**. Кода нет, спроектирована постановка — см.
[#1](https://github.com/po-helper-org/poh-delivery-agent/issues/1).

## Зачем отдельный репозиторий

Агент разрабатывается, тестируется и версионируется автономно, а в Harness
(`po-helper-org/poh-issue-agents`) подключается как **отдельный модуль**: в контуре
живёт точка подключения, а не код агента. Тот же приём, что у `poh-sysreq-agent`.

## Что делает (целевой сценарий)

1. PR одобрен к merge.
2. Изучает актуальное состояние репозитория и открытые PR.
3. Проверяет актуальность и конфликты. Есть конфликт — делегирует агенту разработки
   (цикл Developer + PR-Review).
4. Строит релизную очередь, создаёт релиз в репозитории с подробным планом,
   публикует ссылку на релиз во всех входящих PR.
5. Катит по шагам плана, на каждом шаге проверяет поведение системы;
   при проблеме — откатывает.
6. Дописывает в релиз результат: что сделано, что изменилось для пользователей,
   где выполнены взаимосвязанные изменения.
7. Завершает работу.
